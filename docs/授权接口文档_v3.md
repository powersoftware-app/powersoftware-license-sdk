# 授权开放接口文档 v3

本文档与平台后端实现（`ps-frontend-service` / `ps-worker-dependency`）保持一致，覆盖客户端软件接入授权体系所需的全部开放接口。SDK 三语言（Node / Python / Java）已封装本文档中的接口，封装对应关系见文末对照表。

---

## 一、通用约定

### 1.1 Base URL

```text
https://www.powersoftware.app/frontApi
```

所有接口均为 `POST`，`Content-Type: application/json`。

### 1.2 响应包络

所有接口返回统一结构：

```json
{
  "success": true,
  "code": "SUCCESS",
  "requestId": "req-xxxx",
  "content": { ... }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| success | boolean | `true` 业务成功，`false` 失败 |
| code | string | 成功为 `SUCCESS`；失败为 `BUSINESS_WARNING`（业务失败）/ `PARAM_VALIDATE_FAILED`（参数校验失败）/ `SYSTEM_ERROR`（系统异常） |
| requestId | string | 请求追踪 ID，反馈问题时提供 |
| content | object | 业务数据，仅在 `success=true` 时有意义 |
| tip | string | 本地化错误提示（按请求 `Accept-Language` 返回） |
| errorMessage | string | 业务错误码，如 `LICENSE.error.codeNotFound`，用于程序化分支判断 |

SDK 已将上述包络解包：成功时直接返回 `content`，失败时抛出异常（`errorCode` 即 `code` 字段）。

### 1.3 核心术语

| 术语 | 字段 | 说明 |
| --- | --- | --- |
| 授权码 | `licenseCode` | 平台生成的唯一授权码；Sandbox 测试码带 `T-` 前缀 |
| 机器码 | `machineCode` | 客户端生成的设备标识，至少 8 位；SDK 三语言算法一致（`M` + SHA-256 前 32 位 Base64URL） |
| 激活凭证 | `activationToken` | 平台在激活 / 发码时签发的 HMAC 签名凭证，软件本地保存，启动校验时回传 |
| 版本 | `edition` | 产品版本标识（如 BASIC / PRO / ULTIMATE / TRIAL） |
| 到期时间 | `expiryTime` | ISO8601 字符串，`null` 表示永久 |
| 试用到期快照 | `trialExpiryTime` | 试用转购买后非 `null`，客户端据此决定是否对高档功能保留宽限 |
| 升级策略 | `licenseUpgradeMode` | `SAME_CODE`（原码不变升级）/ `NEW_CODE`（吊销旧码发新码）；`NEW_CODE` 已于 2026-10 停用，发布/编辑页不再提供，新品恒 `SAME_CODE`，字段仍返回以兼容存量 |
| 试用额度 | `trialCount` | 产品级配置（发放 cap 模板），服务端按周期桶记账（`kind=trial`），2.8 `quota/consume` 扣减 |
| 试用额度周期 | `trialCountPeriod` | `TOTAL`（累计，默认，扣完即止）/ `DAILY`（每日重置）/ `WEEKLY`（每周重置，ISO-8601 周）/ `MONTHLY`（每自然月重置）；决定服务端试用桶 key |
| 试用周期 key | `trialPeriodKey` | 重置型周期（`DAILY`/`WEEKLY`/`MONTHLY`）时随响应下发的服务器当前周期 key（`DAILY`=`"2026-09-30"`、`WEEKLY`=`"2026-W39"`、`MONTHLY`=`"2026-09"`），即服务端试用桶 `bucket_key`；新周期落新桶→天然清零（`TOTAL`/未启用为 `'ALL'` 累计桶） |
| 试用下次重置时间 | `trialNextResetTime` | 试用额度「下次重置时间」（UTC 边界时刻，随响应派生）：重置型周期返回当前试用桶滚到下一段的时刻（DAILY→次日 00:00 / WEEKLY→下周一 00:00 / MONTHLY→次月 1 日 00:00），即服务端试用桶 key 变化、余额天然清零那一刻；`TOTAL`/未启用/EDITION 为 `null`；是 `quotaNextExpiry` 在试用侧的对称字段 |
| 计费周期 | `billingPeriod` | `PERMANENT`（永久）/ `MONTHLY`（按月）/ `YEARLY`（按年）；购买/升级时刻固化到授权码上，随所有授权响应透出；存量老码与试用码回退 `PERMANENT`；另可作为 2.6 升级/续费的请求参数指定目标周期 |
| 授权计费模型 | `licensePricingModel` | 产品级配置：`EDITION`（版本分层，默认，支持已购抵扣补差价）/ `QUOTA`（按量额度，售卖额度包）；决定授权购买与额度口径 |
| 额度数量 | `quotaAmount` | QUOTA 额度包随购买固化到**这一张授权码**上的展示总额（= Σ 已发票 cap）；权威可花余额取票聚合 `quotaRemaining`；EDITION、存量与试用码为 `null` |
| 已用额度 | `quotaUsed` | QUOTA 产品专有：本码在**服务端有效票累计已用**额度（`license_usage` 按票(kind, bucket_key)记账，由 2.8 `quota/consume` FIFO 扣减），一张码跨设备/重装共享一份账；EDITION 为 `null` |
| 剩余额度 | `quotaRemaining` | QUOTA 产品专有：Σ 有效票 `max(0, cap - used)`（过期票整票退出），本码剩余；客户端据此拦截，归零引导购买（`consume` 即时返回为最准值，`verify` 最长滞后一个缓存 TTL）；不再取 `quotaAmount - quotaUsed` |
| 额度有效期 | `quotaNextExpiry` | QUOTA 产品专有：未过期且有剩的付费票中最早到期的 `expires_at`（ISO8601）；存在永久有剩票或无有剩票时为 `null`（前端按 `quotaRemaining` 判「永久」/「已用尽」）；`verify` / `activate` / `consume` 均返回；EDITION 为 `null` |
| 软件发码密钥 | `licenseApiSecret` | 产品开启「授权激活」时自动生成，仅保存在软件服务端，严禁写入客户端 |

> 说明：`billingPeriod` 存储在授权记录上（购买/升级/续费时刻固化），`verify` / `activate` / `trial/claim` / `software/generate` / `software/upgrade` 响应均返回该字段，客户端可直接用于展示「按月/按年」标识；存量老码与试用码为 `PERMANENT`。

> 按量额度（`licensePricingModel = QUOTA`）：产品以「额度包」售卖（如 20 次 / 100 次，可各配有效期，此时 `billingPeriod` 语义为「额度有效期」），额度数量 `quotaAmount` 随购买固化到授权码；平台不做已购抵扣、不拦降级。额度累加方式取决于产品「升级策略」：① `SAME_CODE`（原码升级，默认）——同机复购时新额度在**服务端累加到同一张码**（`quotaAmount = 原额度 + 本单额度`），到期时间叠加顺延（`base = max(now, 旧到期) + 本包有效期`，永久码保持永久），`verify` / `activate` 返回的即**当前总额度**，客户端无需自行累加；② `NEW_CODE`（换新码）——每单发一张独立新码、旧码保持有效，**每张码是一个独立钱包**，客户端按当前持有的码取用。**用量记账走服务端**：每次功能调用调 2.8 `POST /license/quota/consume`，平台在该码的 `quota_used` 上原子有界扣减（`quota_used + amount <= quota_amount`），同一码跨设备/重装共享同一份账；响应回带本码 `quotaUsed` / `quotaRemaining` 作可信余额。EDITION 产品与存量/试用码的 `quotaAmount` 恒为 `null`。

### 1.4 字段与计费模型对照（EDITION / QUOTA）

产品二选一计费模型（产品级 `licensePricingModel`），下表标注每个字段的适用模型（不适用的字段恒 `null`，客户端容错显示 `-`）：

| 字段 | 适用模型 | 说明 |
| --- | --- | --- |
| `licenseCode` / `machineCode` / `activationToken` / `status` | 通用 | 授权码 / 机器码 / 激活凭证 / 状态 |
| `productUniqueCode` / `source` / `maxMachines` / `activatedMachines` | 通用 | 产品编码 / 来源 / 机器数上限与已绑 |
| `edition` | 通用（语义不同） | EDITION 为档位；QUOTA 恒单一基本版（可 `null`） |
| `softwareMajorVersion` / `trialDays` / `trialExpiryTime` / `licenseDeductionEnabled` | EDITION | 大版本 / 按天试用 / 宽限快照 / 升级补差价 |
| `billingPeriod` | **双语义** | EDITION→订阅周期（驱动码 `expiryTime`/续费）；QUOTA→每张额度票的有效期周期（逐票 `expires_at`） |
| `quotaAmount` / `quotaUsed` / `quotaRemaining` / `quotaNextExpiry` | QUOTA | 展示总额 / 已用 / 剩余 / 额度有效期；**`quotaAmount` 对 EDITION 恒 `null`** |
| `trialCount` / `trialCountPeriod` / `trialPeriodKey` / `trialUsed` / `trialRemaining` / `trialNextResetTime` | QUOTA | 按次试用额度/周期/桶 key/已用/剩余/下次重置时间；**对 EDITION 恒 `null`**（试用维度与 EDITION 互斥） |
| `consume`（`kind: 'quota' | 'trial'`） | QUOTA | 额度消耗接口；EDITION 不调用 |

> 要点：两模型的试用维度互斥（EDITION 按天 `trialDays`、QUOTA 按次 `trialCount`）；`billingPeriod` 一词两义，按产品 `licensePricingModel` 读取；QUOTA 码不因额度耗尽而 `expired`，额度只影响 `quotaRemaining`。

### 1.5 通用规则

- **限流**：`activate` / `verify` 按同一 IP + 同一授权码统计失败次数（10 分钟窗口），超限返回 `tooManyAttempts`。客户端收到后应拉长重试间隔，不要密集重试。
- **校验缓存**：`verify` 结果服务端有缓存（Cache API + KV 双层），吊销 / 解绑 / 升级等写操作会主动失效缓存，额度（consume/addQuota）变更按**单码跨全部机器**失效其缓存；SDK 本地另有 60s 缓存（`verifyCached`）。发布过渡期内旧缓存条目可能缺 `billingPeriod` 字段，客户端应按「缺省 = `PERMANENT`」处理。
- **幂等**：`software/generate` / `software/upgrade` 按「产品 + `clientOrderId`」幂等，重复请求不会重复发码。`software/addQuota` 按 `clientOrderId` 做**订单级幂等**（传了才生效）：首次请求抢占标记，同单重放直接返回首次结果，并发重复返回 `quotaOrderProcessing`（处理中，稍后重试，勿换单号重发）；标记保留 7 天，处理中断 2 分钟自动释放不永久堵单。**未传 `clientOrderId` 时平台无法判重**，同一订单的重复发放会真的重复加额度，须由软件服务端自行去重。
- **时间戳防重放**：签名接口的 `timestamp` 与服务器时间差不得超过 5 分钟。

### 1.6 签名规则（software/generate、software/upgrade）

**签名串**（按固定顺序、换行 `\n` 分隔）：

```text
productUniqueCode 
 machineCode 
 edition 
 expiryDays 
 clientOrderId 
 licenseCode 
 billingPeriod 
 timestamp
```

- 缺省字段以空字符串 `''` 填充，`expiryDays` 缺省填 `0`；`billingPeriod` 归一为 trim + 大写（generate 无该字段时填 `''`）
- 签名：`HMAC-SHA256(licenseApiSecret, 签名串)`，结果 Base64URL 编码后放入 `signature` 字段
- `timestamp` 为毫秒时间戳
- 兼容窗口：`billingPeriod` 已纳入签名；过渡期内服务端仍接受不含该段的旧 7 段签名，存量客户端升级后旧签名将被拒绝

> **`software/addQuota` 用独立签名串**（与上面的 8 段串互不影响，不影响存量 SDK）：
> ```text
> productUniqueCode 
 licenseCode 
 addAmount 
 quotaType 
 clientOrderId 
 edition 
 timestamp
> ```
> `quotaType` 归一 trim + 大写（缺省 `QUOTA`），`edition` 缺省 `''`，`addAmount` 原样取整数值；SDK 用 `signAddQuota` / `sign_add_quota` 生成。

## 二、接口明细

### 2.1 激活（/license/activate，无需登录）

**调用时机**：用户打开客户端软件进入激活页输入授权码，软件读取机器码随请求带上；解绑后重新激活同一台机器亦复用本接口。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| licenseCode | string | 是 | 用户购买的授权码，≥10 位 |
| machineCode | string | 是 | 客户端生成的机器码，≥8 位 |

**成功响应 `content`**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| licenseId | number | 授权记录 ID |
| licenseCode | string | 授权码 |
| productUniqueCode | string | 产品唯一编码 |
| edition | string/null | 当前版本标识 |
| machineId | number | 绑定机器记录 ID |
| activatedAt | string | 激活时间（ISO8601） |
| expiryTime | string/null | 到期时间，`null`=永久 |
| trialExpiryTime | string/null | 试用到期快照，试用转购买后非 `null` |
| billingPeriod | string | 计费周期：`PERMANENT` / `MONTHLY` / `YEARLY`；存量码与试用码为 `PERMANENT` |
| quotaAmount | number/null | QUOTA 额度：本码展示的总额（= Σ 已发票 cap）；权威可花余额取 `quotaRemaining`；EDITION/存量/试用码为 `null` |
| quotaUsed | number/null | QUOTA 产品：本码服务端**有效票累计已用**（`license_usage` 按票聚合，由 2.8 `quota/consume` 扣减，同一码跨设备/重装共享一份账）；EDITION/非 QUOTA 为 `null` |
| quotaRemaining | number/null | QUOTA 产品：本码剩余 = Σ 有效票 `max(0, cap - used)`（过期票整票退出）；EDITION/非 QUOTA 为 `null` |
| maxMachines | number | 单码最大绑定机器数 |
| activationToken | string | **激活凭证，软件必须保存**，启动校验时回传 |
| licenseUpgradeMode | string | `SAME_CODE` / `NEW_CODE`（NEW_CODE 已停用），据此决定是否展示绑定授权码输入框 |
| trialCount | number/null | 版本试用额度（发放 cap 模板），服务端按周期桶记账 |
| trialUsed | number/null | 试用额度：当前周期桶已用（服务端记账）；`trialCount` 未启用为 `null` |
| trialRemaining | number/null | 试用额度：当前周期桶剩余；`trialCount` 未启用为 `null` |
| trialCountPeriod | string | 试用额度周期：`TOTAL` 累计 / `DAILY`/`WEEKLY`/`MONTHLY` 每自然日/周/月重置（旧缓存条目缺省视为 `TOTAL`） |
| trialPeriodKey | string/null | 重置型周期（`DAILY`/`WEEKLY`/`MONTHLY`）时的服务器周期 key（`DAILY`=YYYY-MM-DD、`WEEKLY`=ISO 周 YYYY-Www、`MONTHLY`=YYYY-MM，均为 UTC），即服务端试用桶 key；其余为 `null` |
| trialNextResetTime | string/null | 试用额度下次重置时间（UTC，服务端派生）：重置型周期当前桶滚到下一段的边界时刻，客户端据此展示「何时清零」；`TOTAL`/未启用为 `null`；是 `quotaNextExpiry` 的试用侧对称字段 |

**本接口错误码**（`errorMessage` 中 `LICENSE.error.` 后缀）：`codeNotFound`、`revoked`、`expired`、`productNotEnabled`、`machineLimit`、`tooManyAttempts`。

### 2.2 启动校验（/license/verify，无需登录）

**调用时机**：每次软件启动或解锁付费功能前调用；需回传激活时保存的 `activationToken`。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| licenseCode | string | 是 | 软件本地保存的授权码，≥10 位 |
| machineCode | string | 是 | 当前设备机器码，≥8 位 |
| activationToken | string | 是 | 激活时平台签发的凭证，≥20 位 |

**成功响应 `content`**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| valid | boolean | 恒为 `true`（失败走错误码） |
| licenseId | number | 授权记录 ID |
| productUniqueCode | string | 产品唯一编码 |
| edition | string/null | 当前版本标识 |
| expiryTime | string/null | 到期时间，`null`=永久；软件据此判断是否过期停用功能 |
| trialExpiryTime | string/null | 试用到期快照 |
| billingPeriod | string | 计费周期：`PERMANENT` / `MONTHLY` / `YEARLY`；随结果入缓存，过渡期旧缓存条目可能缺省（视为 `PERMANENT`） |
| quotaAmount | number/null | QUOTA 额度：本码展示的总额（= Σ 已发票 cap）；EDITION/存量为 `null`，随结果入缓存，旧缓存条目缺省视为 `null` |
| quotaUsed | number/null | QUOTA 产品：本码服务端**有效票累计已用**（`license_usage` 按票聚合，由 2.8 `quota/consume` 扣减，同一码跨设备/重装共享这一份账）；EDITION/旧缓存为 `null`；随结果入缓存，consume 后按单码跨机器失效重算，最长滞后一个 TTL |
| quotaRemaining | number/null | QUOTA 产品：本码剩余 = Σ 有效票 `max(0, cap - used)`（过期票整票退出），服务端权威余额；启动校验据此对齐本地计数（consume 即时返回为最准值）。与 `quotaAmount`/`quotaUsed` 同样随 verify 结果入缓存 |
| trialUsed | number/null | 试用额度：当前周期桶已用（服务端 `kind=trial` 桶记账）；`trialCount` 未启用为 `null` |
| trialRemaining | number/null | 试用额度：当前周期桶剩余；`trialCount` 未启用为 `null` |
| licenseUpgradeMode | string | `SAME_CODE` / `NEW_CODE`（NEW_CODE 已停用），随结果入缓存 |
| trialCount | number/null | 版本试用额度，随结果入缓存 |
| trialCountPeriod | string | `TOTAL` 累计 / `DAILY`/`WEEKLY`/`MONTHLY` 每自然日/周/月重置，随结果入缓存 |
| trialPeriodKey | string/null | 重置型周期（`DAILY`/`WEEKLY`/`MONTHLY`）时的服务器周期 key（`DAILY`=YYYY-MM-DD、`WEEKLY`=ISO 周 YYYY-Www、`MONTHLY`=YYYY-MM，均 UTC），客户端按 key 变化本地清零；随结果入缓存，跨周期重置最长滞后一个缓存 TTL |
| trialNextResetTime | string/null | 试用额度下次重置时间（UTC，服务端派生）：重置型周期当前桶滚到下一段的边界时刻；`TOTAL`/未启用为 `null`；随结果入缓存，跨周期最长滞后一个缓存 TTL |

**本接口错误码**：`tokenInvalid`（凭证无效/被篡改/跨环境冒用）、`machineNotActivated`、`invalidOrRevoked`、`expired`、`productNotEnabled`、`productNotAvailable`（产品未上架）、`tooManyAttempts`。

> **服务端额度记账**：QUOTA 产品的用量不再依赖本地（跨浏览器/跨笔记本/重装不可控），应在每次功能调用时改调 2.8 `/license/quota/consume`，并以响应/verify 的 `quotaRemaining`（付费票聚合）/ `trialRemaining`（试用周期桶）作为唯一可信余额。

### 2.3 解绑设备（/license/deactivate，需登录）

**调用时机**：用户在个人中心「我的授权」对旧设备解绑，然后在新设备调用 2.1 激活。SDK 不封装登录态，浏览器场景由站点个人中心调用。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| licenseCode | string | 是 | 要解绑的授权码，≥10 位 |
| machineCode | string | 是 | 要解绑的机器码，≥8 位 |

**成功响应 `content`**：`true`

**解绑配额**：解绑后 N 天内不可再次解绑（默认 30 天，运营可配），防止无限轮换。

**本接口错误码**：`noPermission`（授权码不存在或非本人）、`machineNotBound`、`unbindQuotaExceeded`。

### 2.4 领取试用授权（/license/trial/claim，无需登录）

**调用时机**：产品为「先用后付（TRIAL_FIRST）」模式时，用户 0 元下载后客户端调用；按「产品 + 机器码」幂等，重复调用返回同一试用授权。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| productUniqueCode | string | 是 | 产品唯一编码 |
| machineCode | string | 是 | 客户端生成的机器码，≥8 位 |

**成功响应 `content`**：与 2.1 激活响应字段完全一致（含 `activationToken`、`licenseUpgradeMode`、`trialCount` 及其附带的 `trialCountPeriod` / `trialPeriodKey`），试用到期时间在 `expiryTime` 中。

**本接口错误码**：`productIdRequired`、`machineCodeInvalid`、`productNotFound`、`productNotEnabled`、`trialNotEnabled`（非先用后付产品）、`productNotAvailable`、`trialAlreadyPurchased`（该机器已绑定非试用授权）。

### 2.5 软件内支付发码（/license/software/generate，HMAC 签名）

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| productUniqueCode | string | 是 | 产品唯一编码 |
| machineCode | string | 是 | 客户端机器码，≥8 位 |

| billingPeriod | string | 否 | 目标计费周期：`MONTHLY` / `YEARLY` / `PERMANENT`；同一版本配多条周期时指定发哪条，缺省取该版本配置首行；决定固化到码上的 `billingPeriod` 与 QUOTA 额度 |
| clientOrderId | string | 是 | 软件内支付订单号（1-64 位），保证全局唯一 |
| timestamp | number | 是 | 毫秒时间戳，±5 分钟内有效 |
| signature | string | 是 | HMAC 签名，见 1.6 |

**成功响应 `content`**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| licenseId | number | 授权记录 ID |
| licenseCode | string | 新生成的授权码 |

| machineId | number | 预绑定机器记录 ID |

| expiryTime | string/null | 到期时间，`null`=永久 |
| trialExpiryTime | string/null | 试用到期快照 |
| billingPeriod | string | 计费周期：`PERMANENT` / `MONTHLY` / `YEARLY`；按命中的版本配置行固化到码上（缺省该版本首行，无周期配置回退 `PERMANENT`） |
| quotaAmount | number/null | QUOTA 额度：`software/generate` 按命中的 QUOTA 配置行固化本包额度数量，随响应返回；EDITION 产品（配置行无额度）与存量为 `null` |

**本接口错误码**：`productIdRequired`、`machineCodeInvalid`、`orderIdRequired`、`productNotFound`、`productNotEnabled`、`apiSecretMissing`、`signatureInvalid`、`productNotAvailable`、`orderAlreadyUsed`（同订单号已发码但机器未绑定）。

### 2.6 软件内升级/续费（/license/software/upgrade，HMAC 签名）

**调用时机**：软件内二次开通高档版本或续费后，由软件服务端带签名调用。按产品配置的升级策略（`licenseUpgradeMode`）处理：

- `SAME_CODE`：原码升级 edition 并顺延有效期，机器绑定不失效
- `NEW_CODE`：吊销旧码、发新码并迁移全部机器绑定，当前机器补发新 `activationToken`

> **QUOTA（按量额度）产品不准调本接口**：升级只改版本/计费周期/到期时间、**不动 `quotaAmount`**，对额度产品误调会静默丢额度（尤其 `NEW_CODE` 下新码不带额度、旧码被吊销），平台直接拒绝并返回 `quotaUpgradeUseAddQuota`。续额度请走用户在平台复购（自动累加）或 2.6.1 `software/addQuota`。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| productUniqueCode | string | 是 | 产品唯一编码 |
| licenseCode | string | 是 | 软件当前保存的授权码（原码），≥10 位 |
| machineCode | string | 否 | 客户端机器码；`NEW_CODE` 策略下用于迁移后补绑并签发新凭证 |
| edition | string | 是 | 升级目标版本（≤50 位，须在产品版本配置内） |
| expiryDays | number | 否 | 续费时长（天，0-3650）；仅永久版兼容此参数行为 |
| billingPeriod | string | 否 | 目标计费周期：`MONTHLY` / `YEARLY` / `PERMANENT`；同一版本配置多条周期时指定升级到哪条，缺省取该版本配置首行 |
| clientOrderId | string | 是 | 本次订单号（幂等） |
| timestamp | number | 是 | 毫秒时间戳，±5 分钟内有效 |
| signature | string | 是 | HMAC 签名，见 1.6 |

**计费周期与续费顺延**：

- 周期版（`MONTHLY` / `YEARLY`）：新到期 = `max(now, 旧到期)` + 1 个周期（与平台购买链路口径一致）
- 永久版（`PERMANENT`）：保持永久；存量软件发码自定义时长场景兼容 `expiryDays` 参数

**成功响应 `content`**：在 2.5 响应字段基础上增加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| upgraded | boolean | 恒为 `true` |
| oldLicenseId | number | 仅 `NEW_CODE` 策略返回：被吊销的旧授权记录 ID |
| machineId | number | `SAME_CODE` 幂等重放 / 永久兼容路径下为 `0` |
| activationToken | string | 仅 `NEW_CODE` 且当前机器补绑成功时返回新凭证，否则为空字符串 |

**本接口错误码**：2.5 全部 + `licenseCodeRequired`、`codeNotFound`、`revoked`、`quotaUpgradeUseAddQuota`（QUOTA 产品请改走复购 / `addQuota`）。

### 2.6.1 软件 API 增加额度（/license/software/addQuota，HMAC 签名）

**适用**：非平台代收款（开发者自行收款）场景下，为 **QUOTA（按量额度）** 授权码累加额度。试用额度累加到 `trialCount`、付费额度累加到 `quotaAmount`（两个独立额度池）。版本分层（EDITION）产品不适用（其额度调整走 `software/upgrade`）。

**签名**：走 addQuota 专用串（见 1.6），用 SDK `addQuotaForSoftware` / `add_quota_for_software`。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| productUniqueCode | string | 是 | 产品唯一编码 |
| licenseCode | string | 是 | 要加额度的授权码（≥10 位）；`T-` 前缀定位 Sandbox 测试表，否则正式表 |
| addAmount | number | 是 | 本次累加数量（正整数，≤1000000） |
| quotaType | string | 否 | `trial`（累加试用额度 `trialCount`，不改版本）/ `quota`（默认，累加付费额度 `quotaAmount`） |
| edition | string | 否 | 仅 `quota` 生效：加额度同时把码转到该付费版本（禁 `TRIAL`）；`trial` 忽略 |
| clientOrderId | string | 建议必填 | 业务订单号：平台据此做**订单级幂等**（同单重放直接回首次结果，不重复加额度）；不传则平台无法判重 |
| timestamp | number | 是 | 毫秒时间戳，±5 分钟内有效 |
| signature | string | 是 | HMAC 签名（addQuota 专用串），见 1.6 |

**约束与行为**：

- 仅 QUOTA 产品、`ACTIVE` 状态、且属于该 `productUniqueCode` 的码可操作；正式环境需产品已上架并持授权服务单。
- 有效期 / 计费周期不变；`quotaType=trial` 不改版本。
- **幂等**：传了 `clientOrderId` 时平台按订单号做条件写抢占：首次请求写入 `pending`，成功后写结果为 `done`（保留 7 天），同单重放直接返回首次结果不重复累加；并发撞上 `pending` 返回 `quotaOrderProcessing`；请求异常中断时 `pending` 最长 2 分钟后自动释放，不会永久堵单。未传 `clientOrderId` 时平台不做订单级去重（仅 `timestamp` 防重放），重复调用会真的重复累加，须由调用方保证只发一次。
- 成功写库后清除**该码跨全部机器**的 `verify` 缓存，下次校验即反映新额度（额度是单码口径，无需再清兄弟码）；正式环境触发运营审计告警。

**成功响应 `content`**：更新后的授权记录（含新的 `trialCount` / `quotaAmount`、`edition`）。

**错误码**：`productIdRequired`、`licenseCodeRequired`、`productNotFound`、`productNotEnabled`、`apiSecretMissing`、`signatureInvalid`、`quotaAmountInvalid`、`editionRequired`、`codeNotFound`、`revoked`、`noPermission`（非 QUOTA 产品）、`quotaOrderProcessing`（同单并发处理中，稍后重试）。

### 2.7 检查版本更新（/product/updateCheck，无需登录）

**调用时机**：软件启动时检查新版本，`hasUpdate=true` 后自行引导用户到产品详情页下载；网络失败由调用方静默降级。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| productUniqueCode | string | 是 | 产品唯一编码 |
| currentVersion | string | 是 | 客户端当前版本号（≤64 位） |

**成功响应 `content`**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| hasUpdate | boolean | 是否有更新；产品不存在/未上架/未填版本统一返回 `false` |
| latestVersion | string/null | 产品最新版本号 |

### 2.8 额度消耗（/license/quota/consume，无需登录）

**适用产品**：仅按量额度（QUOTA）产品。把“用了多少”从客户端本地 storage 上收到服务端，根治**同一授权码跨浏览器 / 跨笔记本 / 重装后各自一份本地用量导致的多倍消耗**：用量改存服务端 `license_usage` 分票/分桶记账，跨设备共享一份账。付费额度按“票(lot)”发放——每张票自带 `cap` + 各自有效期 `expires_at`，消耗时在“未过期且有剩”的票里**最早到期先扣（FIFO）**，`remaining = Σ 各有效票 (cap - used)`；试用额度按服务端周期桶记账（`kind=trial`）。**授权码不因额度耗尽而 `expired`**：额度耗尽/全部过期只让 `remaining=0` 引导复购。

**调用时机**：用户每消耗一次额度（如调一次付费功能）时上报扣减；客户端**不应再仅依赖本地计数做拦截**，而以本接口返回的 `quotaRemaining`（或启动校验 verify 回传的 `quotaRemaining`）为唯一可信余额。

**鉴权**：与 2.2 `verify` 同族——凭 `activationToken` 验签 + 机器绑定（凭证内的 `machineId`）+ 授权有效；**不读 verify 缓存**（需实时额度）。正式环境需产品已上架。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| licenseCode | string | 是 | 授权码，≥10 位（`T-` 前缀走 Sandbox） |
| machineCode | string | 是 | 当前设备机器码（插件为 `EXT-` Install ID），≥8 位 |
| activationToken | string | 是 | 激活时签发的凭证，≥20 位 |
| amount | number | 是 | 本次消耗数量，正整数（单次上限 100 万） |
| requestId | string | 建议必填 | 客户端幂等键，8–128 位。传了才能防重试重复扣减 |
| kind | string | 否 | 消耗类型：`quota`（默认，扣付费额度票）/ `trial`（扣试用周期桶）；缺省按 `quota` |

**成功响应 `content`**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| consumed | number | 本次实际扣减数量 |
| kind | string | 本次消耗类型（`quota` / `trial`，回显请求） |
| quotaUsed | number/null | 付费额度：有效票累计已用（服务端按票聚合） |
| quotaRemaining | number/null | 付费额度：Σ 有效票 `max(0, cap - used)`；**客户端据此拦截**，归零则引导去购买页 |
| trialUsed | number/null | 试用额度：当前周期桶已用（服务端记账） |
| trialRemaining | number/null | 试用额度：当前周期桶剩余；`trialCount` 未启用为 `null` |
| trialNextResetTime | string/null | 试用额度：当前周期桶下次重置时间（重置型周期派生）；`TOTAL`/未启用为 `null` |

**幂等**（传了 `requestId` 才生效）：按（环境 + 授权码 + `requestId`）做 KV 条件写“抢单”，语义与 addQuota **相反**（重放不能重复扣减，伤用户）：首次扣减并写结果，同请求重放直接返回首次结果不再扣；并发撞上处理中的同 `requestId` 返回 `quotaConsumeProcessing`；额度不足等业务失败不写幂等结果（释放抢占，便于调小金额后重试）。未传 `requestId` 时平台无法判重（仅记日志），客户端重试可能重复扣减，需调用方自行保证幂等。

**并发不超扣**：扣减在未过期且有剩的票里按 FIFO 逐票以原子有界 UPDATE 生效（仅当 `used + take <= cap` 且票未过期时），并发下超出余额的请求拿 0 行→对 shortfall 重拉票再分配重试（最多 3 轮）；全不中→`insufficientQuota`。每笔成功扣减写一行 `license_quota_txn` 流水（记 `kind`/`bucket_key`/`amount`，`request_id` 与授权码组成唯一索引作幂等兜底）。

**余额口径与缓存**：额度是**单码口径**（同一码跨设备/重装共享一份账；consume 只扣当前这张码的票，不会去动同机兄弟码），响应里的 `quotaUsed`/`quotaRemaining`/`trialUsed`/`trialRemaining` 都由服务端 `license_usage` 票聚合得出（`license.quota_amount` 仅作展示总额）。verify 缓存了这些聚合余额，consume 后按**单码跨全部机器**失效重算，最长滞后一个 TTL（~30min），故以 consume 即时返回为准确值。**试用额度（trialCount）已纳入服务端周期桶记账**（`kind=trial`），新周期自然落新桶→天然清零，不再依赖客户端本地计数。

**边界（诚实告知）**：服务端记账只是“提高作弊成本 + 可取证”，**不能**防住“根本不调 consume 的纯本地功能插件”（功能不依赖平台回包就拦不住）；只有当功能真需要服务端能力（如 AI 推理、云资源）时才天然栏截。

**本接口错误码**：`tokenInvalid`、`machineNotActivated`、`invalidOrRevoked`、`expired`、`productNotEnabled`、`productNotAvailable`、`noPermission`（非 QUOTA 产品）、`quotaAmountInvalid`（金额非法/超上限）、`insufficientQuota`（额度不足）、`quotaConsumeProcessing`（同请求并发处理中，稍后重试）、`tooManyAttempts`。

## 四、注意事项

- **密钥只存服务端**：签名只能在你的软件服务端完成，客户端拿到密钥等于授权体系失效；
- **机器码稳定性**：建议直接使用 SDK 的 `machineCode()`（本地持久化 UUID → 硬件序列号 → 系统 ID → 组合信号降级）；重装系统导致机器码变化时，先在个人中心解绑再激活；
- **本地凭证最小化**：客户端只保存 `licenseCode + activationToken + 最近校验结果`，不落盘其他授权信息；
- **有效期判定以平台为准**：`expiryTime`、版本、机器数上限均以平台响应为准，软件端不要自行放宽；
- **计费周期展示**：`billingPeriod` 由平台在购买/升级时刻固化并随响应下发，客户端只做展示，不要据此自行推导到期时间；
- **环境隔离**：Sandbox 测试码带 `T-` 前缀，激活/校验/解绑自动路由到测试表；`activationToken` 内含环境标识，跨环境回传会被 `tokenInvalid` 拒绝。
