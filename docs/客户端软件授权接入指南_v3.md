# 客户端软件授权接入指南（v3）

> 适用于：在幂栈网发布客户端软件，集成授权 SDK 实现版本控制与付费功能拦截。
> SDK 仓库：[github.com/mizhanchengxi/powersoftware-license-sdk](https://github.com/mizhanchengxi/powersoftware-license-sdk)
> 关联文档：[授权 SDK 规范](授权SDK规范_v3.md) ｜ [售卖方式与授权购买链路](售卖方式与授权购买链路_v3.md)

## 一、两种接入场景

幂栈网为客户端软件提供两种授权接入方式，开发者根据自身情况选择：

| | 场景 A：平台完整链路（先用后付） | 场景 B：订单不在平台 |
|---|---|---|
| **适用产品** | 客户端软件 + `TRIAL_FIRST` 售卖方式 | 客户端/服务端软件，自行收款 |
| **谁管收款** | 幂栈网平台（支付宝 / PayPal） | 开发者自己（软件内支付或其他渠道） |
| **谁管发码** | 平台支付成功后自动发码 | 软件调平台 API 发码（HMAC 签名） |
| **需要 `apiSecret`？** | ❌ 不需要 | ✅ 需要（仅存服务端，不可存客户端） |
| **需要服务端？** | ❌ 不需要，纯客户端即可 | ✅ 需要（保管 `apiSecret`，转发发码请求） |
| **试用授权** | ✅ 支持（`claimTrial`） | ❌ 无试用 |
| **购买页** | 平台提供，SDK 一行跳转 | 无平台购买页，开发者自行处理 |

> **关于版本配置**：所有产品形态（客户端/服务端/仅推广）均可启用授权码并自定义版本（BASIC/PRO/ULTIMATE 等）。版本价格和功能清单仅在开发者勾选「平台代收授权费」（`licensePlatformPayment`）时展示在购买页；不勾选则开发者自行处理收款，平台仅提供授权码发放与校验能力。

### 如何选择

- **你是独立开发者 / 小团队，没有自己的服务端** → 选 **场景 A**
- **你已有支付渠道（如微信/支付宝商户），只想用平台发码校验** → 选 **场景 B**

## 三、场景 A：平台完整链路（先用后付）

### 3.1 前置条件

1. 在幂栈网发布产品，售卖方式选 **先用后付（TRIAL_FIRST）**
2. 填写试用天数（如 7 天）
3. 配置授权版本（edition），默认三档，开发者可自定义：
   - `BASIC` — 基础版
   - `PRO` — 高阶版
   - `ULTIMATE` — 旗舰版
4. 勾选「平台代收授权费」（TRIAL_FIRST 强制勾选；PAY_FIRST 可选）
5. 记下 `productUniqueCode`（发布页可见，非密钥）

### 3.2 初始化

**不需要 `apiSecret`**。`apiSecret` 仅用于场景 B 的发码签名，场景 A 完全不涉及。

```python

from ps_license_sdk import LicenseClient, machine_code

client = LicenseClient(product_unique_code="PRO-2026-001", api_secret="")  # api_secret 留空
mc = machine_code()
```


### 3.3 完整接入流程

```
首次启动
    │
    ├─ claimTrial(machineCode) ──────────────────→ 获取试用授权
    │     ↓ 返回 { licenseCode, activationToken, licenseUpgradeMode }
    │     ↓ 本地持久化存储
    │
    ├─ 试用期内：所有功能可用
    │     │
    │     └─ 点击付费功能 → verifyCached() 60s 缓存校验 → 放行
    │
    └─ 试用到期 / 未激活
          │
          ├─ verifyCached() 返回 invalid/expired
          ├─ 弹窗提示"需要购买激活授权"
          └─ purchaseUrl(machineCode) → 跳转平台购买页
                │
                ↓ 用户在平台支付
                │
                ↓ 平台发码 + 邮件送达
                │
          用户回到软件，输入授权码
                │
                ├─ activate(licenseCode, machineCode)
                │     ↓ 返回 { activationToken, licenseUpgradeMode }
                │     ↓ 本地持久化存储
                │
                └─ 后续使用 → verifyCached() 校验 → 放行
```

### 3.4 核心代码

```python
import json
from pathlib import Path
from ps_license_sdk import LicenseClient, machine_code

# ---------- 初始化 ----------
client = LicenseClient(product_unique_code="PRO-2026-001", api_secret="")
CRED_FILE = Path.home() / ".myapp" / "license.json"

def load_cred():
    if CRED_FILE.exists():
        return json.loads(CRED_FILE.read_text())
    return {}

def save_cred(d):
    CRED_FILE.parent.mkdir(parents=True, exist_ok=True)
    CRED_FILE.write_text(json.dumps(d, ensure_ascii=False))

# ---------- 首次启动：领取试用 ----------
def claim_trial():
    mc = machine_code()
    try:
        result = client.claim_trial(mc)
        save_cred({
            "licenseCode": result["licenseCode"],
            "activationToken": result["activationToken"],
        })
        print(f"试用已激活，授权码：{result['licenseCode']}")
    except Exception as e:
        print(f"领取试用失败：{e}")

# ---------- 校验授权（点击付费功能时调用） ----------
def check_license(required_edition="PRO"):
    cred = load_cred()
    if not cred.get("licenseCode"):
        return {"valid": False, "reason": "未激活"}

    mc = machine_code()
    try:
        result = client.verify_cached(
            cred["licenseCode"], mc, cred["activationToken"]
        )
        if not result.get("valid"):
            return {"valid": False, "reason": "授权无效或已过期"}

        user_edition = result.get("edition", "")
        # TRIAL 试用授权=全功能可用，层级取最高（缺省字典漏掉 TRIAL 会导致试用期只剩基础功能！）
        levels = {"BASIC": 0, "PRO": 1, "ULTIMATE": 2, "TRIAL": 99}
        if levels.get(user_edition, 0) < levels.get(required_edition, 0):
            return {"valid": False, "reason": f"需要 {required_edition} 及以上版本"}

        return {"valid": True, "edition": user_edition,
                "expiryTime": result.get("expiryTime"),
                "trialExpiryTime": result.get("trialExpiryTime")}
    except Exception as e:
        return {"valid": False, "reason": str(e)}

# ---------- 激活授权码（用户购买后输入） ----------
def activate(license_code):
    mc = machine_code()
    try:
        result = client.activate(license_code, mc)
        save_cred({
            "licenseCode": license_code,
            "activationToken": result["activationToken"],
        })
        return True
    except Exception as e:
        print(f"激活失败：{e}")
        return False

# ---------- 跳转购买页 ----------
def open_purchase_page():
    mc = machine_code()
    url = client.purchase_url(mc)
    import webbrowser
    webbrowser.open(url)
```

### 3.6 试用转购买的功能宽限（trialExpiryTime）

先用后付产品在试用期内**全功能可用**；用户购买较低版本后，高档功能会因版本门控立即锁定，产生「付了钱功能反而变少」的落差。为此，激活/校验/试用领取三个接口的成功响应均返回 `trialExpiryTime`（原试用授权的到期时间，ISO 8601；非试用转购买为 `null`）：

- 试用后购买（原码升级或换新码）时，平台先查试用码原到期时间并固化到本字段，购买后 `expiryTime` 变为所购版本有效期，本字段保持不变；
- 过期试用转购买同样固化（值为过去时刻），可用于识别「无宽限」；
- 后续付费升级/续费保留该字段。

客户端可据此自行决定过渡策略，例如：试用到期前继续放行高档功能（宽限期），到期后再锁定并引导补差价升级：

```python
def feature_allowed(check_result, required_edition="ULTIMATE"):
    """版本不足时，若仍在原试用到期时刻之前，则给高档功能保留宽限"""
    if check_result["valid"]:
        return True
    levels = {"BASIC": 0, "PRO": 1, "ULTIMATE": 2}
    if levels.get(check_result.get("edition", ""), 0) >= levels[required_edition]:
        return True
    trial_expiry = check_result.get("trialExpiryTime")
    if not trial_expiry:  # 非试用转购买，或试用已过期：无宽限
        return False
    from datetime import datetime, timezone
    return datetime.now(timezone.utc) < datetime.fromisoformat(trial_expiry.replace("Z", "+00:00"))
```

是否使用该字段、宽限方式（放行时长、UI 提示、是否倒计时引导升级）由客户端自行决定，平台不做强制。

### 3.7 计费周期与续期顺延（billingPeriod）

平台版本可配置三种计费周期：`PERMANENT`（永久买断，默认）、`MONTHLY`（按月，固定 30 天）、`YEARLY`（按年，固定 365 天）。购买页价格按周期展示（`/月`、`/年`，永久无后缀），到期提醒邮件也会在到期前 7 天自动发送。

对接入方的含义：

- **`expiryTime` 语义**：周期版授权的 `verify` / `activate` 返回固定到期日（ISO 8601），到期后 verify 返回 `expired` 错误码，按既有过期逻辑弹购买提示即可；永久版 `expiryTime` 为 `null`。客户端无需（也无法）从 SDK 接口感知周期类型，如需展示「按月/按年」标识，以购买页版本配置为准；
- **软件内升级/续费指定周期**：同一版本可配多条计费周期时，`upgradeForSoftware` 可传可选参数 `billingPeriod`（`PERMANENT`/`MONTHLY`/`YEARLY`）指定升级到哪条周期；缺省取该版本配置首行。周期版升级按 `base = max(now, 旧到期)` 顺延有效期，详见 SDK 规范 3.0 节；
- **续期顺延**：用户在到期前续购（平台购买页或软件内续购均可），新有效期自动在**原到期时间**基础上顺延（`base = max(now, 旧到期)`），不损失剩余时长；过期后续购从当前时间起算。SDK 与接入代码无需做任何处理，平台侧统一实现；
- **到期提醒**：平台每日扫描，对 7 天内到期的周期授权码自动发送提醒邮件（引导用户在软件内续购），SDK 无需感知。

### 3.8 试用额度（trialCount / trialCountPeriod）

与按时间试用的 `trialDays` 并存的第二套试用模式：产品可配置**试用额度**（产品级，与计费周期无关、不同周期不累加），适用于插件等「按功能调用扣减额度」的场景。

- **配置入口**：发布产品页授权版本的「试用额度」——该字段只在产品按**按量额度（QUOTA）**模型发布时展示与启用（版本分层 EDITION 只按天试用，无试用额度维度，平台也不会自动预置默认额度）；启用额度后可选**额度周期**：累计（`TOTAL`，默认，总额度扣完即止）、每日重置（`DAILY`）、每周重置（`WEEKLY`，按 ISO-8601 自然周）或每月重置（`MONTHLY`，按自然月）；
- **下发方式**：`claimTrial` / `activate` / `verify` 成功响应返回 `trialCount`（产品级配置值；未启用为 `null`），并附带 `trialCountPeriod` 与 `trialPeriodKey`（重置型周期 `DAILY`/`WEEKLY`/`MONTHLY` 时为服务器当前周期 key，如 `DAILY="2026-09-30"`、`WEEKLY="2026-W39"`、`MONTHLY="2026-09"`；`TOTAL`/未启用为 `null`）。平台**不记录消耗**，试用额度的扣减、重置由客户端/插件本地自行记录（例如 `chrome.storage.local`）；
- **重置口径**：本地用量建议按 `{ periodKey, used }` 结构持久化——存储的 `periodKey` 与最新响应的 `trialPeriodKey` 不一致时清零并按新 key 重新计数；一致时继续累加。**周期边界以服务器下发的 `trialPeriodKey` 为准，勿用本地时钟判定**，否则用户改系统时间即可提前刷新额度；每周期额度独立，未用完不结转；
- **到期口径**：试用额度归零即视为试用结束，按 `expired` 同等体验处理（引导购买）；`TOTAL` 模式行为与存量完全一致，不感知周期字段也不会出错；
- **两者并存**：`trialDays`（时间）与 `trialCount`（额度）可同时配置，任一先到即试用结束（重置型周期下额度按自然日/周/月恢复，到期仍以 `trialDays` 时间为准）。

### 3.9 按量额度产品（licensePricingModel = QUOTA / quotaAmount）

产品在发布页可选「版本分层（`EDITION`，默认）」或「按量额度（`QUOTA`）」售卖。QUOTA 产品只有一个「基本版」，卖的是**额度包**（如 9.9 元 20 次、20 元 100 次），每包可配有效期（此时 `billingPeriod` 语义为**额度有效期**）。对接入方意味着：

- **不抵扣、不拦降级**：额度包复购永远全价，不存在按已购余额折价的履约逻辑；
- **额度固化到码**：平台下单发码时把本包 `quotaAmount` 写入授权码，`activate` / `verify` 响应随带该字段（EDITION 产品、存量码与试用码恒为 `null`）；
- **额度累加方式 = 产品的「升级策略」**（发布页配置）：
  - **原码升级（`SAME_CODE`，默认）**：同机复购时平台把新额度**累加到原授权码**、到期时间叠加顺延（永久码保持永久），`verify` 返回的 `quotaAmount` 即**当前总额度**，客户端直接取用、无需自行累加；
  - **换新码（`NEW_CODE`）**：每单发一张独立新码、旧码保持有效，客户端需把同机同产品的**多张有效码的 `quotaAmount` 求和**作为总额度；
- **消耗记账在客户端**：平台只管「卖了多少额度、码上剩多少额度」，每次功能调用扣 1、额度归零拦截、余额展示均由软件端实现；建议本地持久化 `{ licenseCode, quotaTotal, used }`，`quotaTotal` 每次 `verify` 后用响应值覆盖（`SAME_CODE` 下响应已含累加结果，天然纠偏本地少记/多记）；
- **免费额度用 `trialCount`**（见 3.8），不用 `trialDays`；购买页无需任何适配，额度包自动渲染为版本卡片内的子卡（标题=额度数量，副标=有效期）。

## 四、场景 B：订单不在平台

### 4.1 前置条件

1. 在幂栈网发布产品，授权码功能开启（`licenseEnabled = true`）
2. 在开发者后台获取 `licenseApiSecret`（**仅存服务端，不可泄露到客户端**）
3. 记下 `productUniqueCode`

### 4.2 架构

```
客户端                        你的服务端                      幂栈网平台
  │                              │                              │
  │  用户付费（你的支付渠道）      │                              │
  ├─────────────────────────────→│                              │
  │                              │  generateForSoftware(        │
  │                              │    machineCode, edition,     │
  │                              │    clientOrderId)            │
  │                              │  (HMAC 签名 + timestamp)      │
  │                              ├─────────────────────────────→│
  │                              │                              │
  │                              │  ← 返回 licenseCode          │
  │  ← 返回 licenseCode         │                              │
  │                              │                              │
  │  activate(licenseCode, mc)   │                              │
  ├────────────────────────────────────────────────────────────→│
  │  ← 返回 activationToken     │                              │
  │                              │                              │
  │  verifyCached(...)          │                              │
  ├────────────────────────────────────────────────────────────→│
  │  ← { valid, edition, expiryTime }                          │
```

### 4.3 核心代码

**服务端（保管 apiSecret）：**

```python

    product_unique_code="PRO-2026-001",
    api_secret="你的发码密钥_FROM_DEVELOPER_CONSOLE",

    """用户付款后，服务端调平台发码"""
    result = server_client.generate_for_software(
        machine_code_value=user_machine_code,
        edition=edition,
        expiry_days=365,
        client_order_id=order_id,
    )
    return result["licenseCode"]
```

## 五、SDK 方法速查

| 方法 | 场景 A | 场景 B | 签名 | 说明 |
|---|:---:|:---:|:---:|---|
| `machine_code()` | ✅ | ✅ | — | 生成机器码（跨语言一致） |
| `claim_trial(mc)` | ✅ | — | — | 领取试用授权（仅先用后付产品） |
| `activate(code, mc)` | ✅ | ✅ | — | 激活授权码，绑定机器 |
| `verify(code, mc, token)` | ✅ | ✅ | — | 校验授权状态 |
| `verify_cached(code, mc, token)` | ✅ | ✅ | — | 带本地缓存（60s）的校验 |
| `deactivate(code, mc)` | ✅ | ✅ | — | 解绑机器（需登录，浏览器场景） |
| `purchase_url(mc)` | ✅ | — | — | 生成平台购买页 URL |
| `check_update(currentVersion)` | ✅ | ✅ | — | 检查版本更新，返回最新版本号与是否有更新 |
| `generate_for_software(mc, edition, ...)` | — | ✅ | HMAC | 软件内发码（仅服务端） |
| `upgrade_for_software(code, edition, ...)` | — | ✅ | HMAC | 软件内升级/续费（仅服务端） |

> **返回字段说明**：`activate` / `verify` / `claim_trial` 的成功响应额外附带 `licenseUpgradeMode`（产品升级策略：`SAME_CODE` 原码不变 / `NEW_CODE` 原码换绑）。客户端据此决定是否展示「绑定授权码」输入框：`SAME_CODE` 下授权码始终不变，无需引导用户重新输入；`NEW_CODE` 下升级/续费后须以接口返回的新码覆盖本地存储。产品未配置时返回 `SAME_CODE`。
>
> 同三个接口还返回 `trialExpiryTime`（原试用授权到期时间，试用转购买后非 `null`），供客户端实现高档功能宽限期，详见 3.6 节。
>
> 同三个接口还返回 `trialCount`（当前授权版本的试用额度配置，未启用为 `null`；平台不记录消耗，扣减由客户端本地实现），以及 `trialCountPeriod`（`TOTAL` 累计 / `DAILY`/`WEEKLY`/`MONTHLY` 每自然日/周/月重置）与 `trialPeriodKey`（重置型周期时的服务器周期 key），详见 3.8 节。

### 5.1 检查版本更新（checkUpdate）

```python
result = client.check_update("1.2.0")
# 返回 { "hasUpdate": True, "latestVersion": "1.3.0" }
# 产品不存在/未上架/无版本信息时返回 { "hasUpdate": False, "latestVersion": None }
```

```javascript
const result = await client.checkUpdate('1.2.0');
// { hasUpdate: true, latestVersion: '1.3.0' }
```

```java
Map<String, Object> result = client.checkUpdate("1.2.0");
```

接入建议：

- **调用时机**：软件启动时异步调用，成功后间隔 ≥ 6 小时再查；服务端已做长缓存，单次请求成本极低。
- **提示升级**：`hasUpdate=true` 时弹窗提示新版本 `latestVersion`，引导用户打开产品详情页下载（详情页地址可由 `purchase_url(mc)` 同站点拼接，或从产品发布页获取）。
- **静默降级**：网络失败/异常时捕获错误直接跳过，绝不阻塞软件主流程。

```python
def check_update_quietly(client, current_version):
    try:
        return client.check_update(current_version)
    except Exception:
        return {"hasUpdate": False, "latestVersion": None}  # 网络异常静默降级
```

## 六、本地凭证存储规范

SDK 本身不负责持久化，由开发者自行实现。存储内容：

```json
{
  "licenseCode": "XXXXXXXXXXXX",
  "activationToken": "YYYYYYYYYYYY",
  "lastVerify": {
    "valid": true,
    "edition": "ULTIMATE",
    "expiryTime": 1735689600000,
    "trialExpiryTime": 1735000000000,
    "cachedAt": 1735689600000
  }
}
```

**原则：**
- 只存 `licenseCode` + `activationToken` + 最近一次 verify 结果
- 不存可解密的完整授权信息（防逆向无意义，只作缓存）
- `verifyCached` 的 60s 缓存在 SDK 进程内，重启后失效，需重新调 `verify`

## 七、版本层级对比

开发者自定义 edition code（如 `BASIC` / `PRO` / `ULTIMATE`），在平台发布页配置。所有产品形态（客户端/服务端/仅推广）启用授权码后均可自定义版本。客户端校验时按层级比较：

```python
# TRIAL 试用授权=全功能可用，层级取最高（漏掉 TRIAL 会导致试用期只剩基础功能！）
EDITION_LEVEL = {"BASIC": 0, "PRO": 1, "ULTIMATE": 2, "TRIAL": 99}

def edition_sufficient(user_edition, required_edition):
    return EDITION_LEVEL.get(user_edition, 0) >= EDITION_LEVEL.get(required_edition, 0)
```

常见映射（参考）：

| 功能档位 | edition code | 层级 | 典型功能 |
|---|---|---|---|
| 基础版 | `BASIC` | 0 | 基础修图、格式转换 |
| 高阶版 | `PRO` | 1 | 批量处理、高清放大 |
| 旗舰版 | `ULTIMATE` | 2 | AI 修复、封面助手 |
| 试用 | `TRIAL` | 99（全功能） | 平台自动发放的试用授权，先用后付产品专属 |

> 版本名称和 code 由开发者在平台自定义，不强制叫 BASIC/PRO/ULTIMATE。版本价格和功能清单仅在勾选「平台代收授权费」时展示在购买页。试用转购买后的高档功能宽限见 3.6 节。

## 八、错误码处理

SDK 抛出 `LicenseError`，携带 `error_code` 属性：

```python
from ps_license_sdk import LicenseError

try:
    result = client.verify_cached(...)
except LicenseError as e:
    if e.error_code == "expired":
        open_purchase_page()
    elif e.error_code == "revoked":
        show_message("授权已被吊销，请联系客服")
    elif e.error_code == "machineLimit":
        show_message("已达机器绑定上限，请在个人中心解绑旧设备")
    elif e.error_code == "NETWORK_ERROR":
        show_message("网络异常，请检查网络后重试")
    else:
        show_message(f"校验失败：{e}")
```

| 错误码 | 含义 | 客户端建议处理 |
|---|---|---|
| `codeNotFound` | 授权码不存在 | 检查输入 |
| `revoked` | 已吊销 | 提示联系客服 |
| `expired` | 已过期 | 引导购买/续费 |
| `machineLimit` | 机器绑定数已满 | 引导去个人中心解绑 |
| `tooManyAttempts` | 触发限流 | 提示稍后重试 |
| `trialNotEnabled` | 产品未开启试用 | 检查平台配置 |
| `trialAlreadyPurchased` | 已购买过该产品（试用领取被拦截） | 提示已购，引导激活/校验既有授权码 |
| `NETWORK_ERROR` | 网络/超时 | 离线宽限或提示重试 |

### 9.2 购买站选择：`.app`（国际站） vs `.cn`（国内站）

| | `powersoftware.app`（国际站） | `powersoftware.cn`（国内站） |
|---|---|---|
| 支付方式 | 支付宝 + PayPal | 仅支付宝 |
| 国家/币种 | Cloudflare 按 IP 自动识别（CN→CNY，其余→USD） | 固定 `country=CN`，人民币 |
| 语言 | 按 URL 前缀 / `Accept-Language` 自动检测 | 固定 `zh-CN` |
| 适用用户 | 国际用户 / 海外 | 中国大陆用户 |

**SDK 默认 `.app`，不做自动判断。** 客户端软件需自行决定传哪个 `base`。

#### 判断方式

**方式一：按系统语言（推荐）**

```python
import locale

def get_purchase_base():
    sys_lang = locale.getdefaultlocale()[0] or ""
    if sys_lang.startswith("zh"):
        return "https://www.powersoftware.cn"
    return "https://www.powersoftware.app"
```

```javascript
function getPurchaseBase() {
    const lang = process.env.LANG || "";
    return lang.toLowerCase().startsWith("zh")
        ? "https://www.powersoftware.cn"
        : "https://www.powersoftware.app";
}
```

```java
String getPurchaseBase() {
    return "zh".equals(Locale.getDefault().getLanguage())
        ? "https://www.powersoftware.cn"
        : "https://www.powersoftware.app";
}
```

**方式二：用户设置项** — 设置界面提供"地区"选项，用户自行选择。

**方式三：硬编码** — 仅面向国内用户的软件直接写死 `base="https://www.powersoftware.cn"`。

> 详见 [语言与国家逻辑](语言与国家逻辑_v3.md) 第 2.4 节。
